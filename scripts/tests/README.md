# `scripts/tests/` — Sanity tests + generated C tests

This directory holds two kinds of file:

1. **`test_pipeline.py`** — a Python test harness that exercises the
   entire generation + dry-run patcher pipeline against the source
   tree. It does **not** require a built RISC-V toolchain.
2. **`<mnemonic>.c`** — small C programs that the *built* compiler
   compiles to verify each generated instruction actually appears in
   the output. They are the inputs to
   [`../05_test.sh`](../05_test.sh).

---

## How to run

### 1. The Python pipeline tests (no toolchain required)

```bash
python3 scripts/tests/test_pipeline.py
```

Expected output:

```
[1] opcode finder                        ✔
[2] config validation                    ✔
[3] arith_expr generation (fds)          ✔
[4] marker generation (bnorm, mem:BLK)   ✔
[5] arith_expr autodetect from raw C     ✔
[6] end-to-end dry-run via 03_apply.py   ✔
[7] customrv.py from-c (way 2)           ✔

  7/7 tests passed
```

This is the file you run after editing anything under `scripts/`.

### 2. The per-mnemonic compiler pattern tests

These are run automatically by `scripts/05_test.sh` (or
`scripts/customrv.py … --build`). To run one by hand against an
already-built toolchain:

```bash
bash scripts/05_test.sh fds   $HOME/riscv-install
bash scripts/05_test.sh nsum  $HOME/riscv-install
bash scripts/05_test.sh fma   $HOME/riscv-install
bash scripts/05_test.sh sinint $HOME/riscv-install
bash scripts/05_test.sh bnorm $HOME/riscv-install
```

Each call compiles `tests/<mnemonic>.c` with `-m<mnemonic> -O2 -S`
and greps the output for the mnemonic; the script exits with `0` if
the instruction is emitted, non-zero otherwise.

## Files

| File | Pattern kind | What it tests |
|------|--------------|---------------|
| [`test_pipeline.py`](./test_pipeline.py) | *all* | Python sanity tests for the generator and dry-run patcher. |
| [`fds.c`](./fds.c) | `arith_expr` | Compiler must rewrite `(a / b) - c` into `IFN_RISCV_FDS(a, b, c)` and emit `fds`. |
| [`nsum.c`](./nsum.c) | `closed_form_loop` | Compiler must rewrite `for (i=0; i<n; ++i) acc += i;` into `IFN_RISCV_NSUM(n)` and emit `nsum`. |
| [`fma.c`](./fma.c) | `marker` (register) | Compiler must rewrite `__custom_fma(a,b,c)` into `IFN_RISCV_FMA` and emit `fma`. |
| [`sinint.c`](./sinint.c) | `marker` (register) | Compiler must rewrite `__custom_sinint(a,b)` into `IFN_RISCV_SININT` and emit `sinint`. |
| [`bnorm.c`](./bnorm.c) | `marker` (register form, generated) | Auto-generated by `c_analyzer.emit_marker_test_c` for marker-style configs. |

## What `test_pipeline.py` actually checks

| # | Check | Why it matters |
|---|-------|----------------|
| 1 | Opcode finder reads `binutils/include/opcode/riscv-opc.h` and the existing `MATCH_ATTN` is recognised. Free-slot search finds at least one R4-type slot. | Catches breakage in `lib/opcodes.py` and confirms the binutils submodule is intact. |
| 2 | `lib/config.py` loads, validates, and derives names for every JSON in `configs/`. | Catches schema regressions. |
| 3 | Generating from `configs/fds.json` produces a `tree-ssa-fds.cc` with the expected matcher tokens (`MINUS_EXPR`, `RDIV_EXPR`, `IFN_RISCV_FDS`) and emits 12 patch JSON files (10 records, two of which split into 1a/1b and 4a/4b). | Catches regressions in the `arith_expr` template / renderer. |
| 4 | The C analyser sees `batchnorm_demo.c` and picks `pattern_kind=marker`, `rtl_kind=memory`, `num_inputs=3`. The emitted RTL block contains `(mem:BLK` and `ghost`. | Catches regressions in pointer-aware marker detection and the memory-style RTL builder. |
| 5 | Auto-detect the `MULT_EXPR + PLUS_EXPR` shape from a one-line C function. | Catches regex/parser regressions in `c_analyzer.detect_arith_expr`. |
| 6 | Run `02_generate.py` then `03_apply.py --dry-run --yes` against the real toolchain tree. Expect 13 DRY entries and zero FAIL. | The end-to-end smoke test for anchor resolution against the actual `gcc/` and `binutils/` source. |
| 7 | `customrv.py from-c` on `examples/fma_demo.c` — strategy `explicit_marker` is detected and a free MATCH/MASK is allocated. | Catches breakage in the unified Way-2 driver. |

If any test fails, fix the underlying issue **before** running
`05_test.sh` or `--build` — by definition there is no point
rebuilding a 7 GiB toolchain over a generation bug.

## Adding a test for a new mnemonic

Two paths:

1. **Marker-style** — let the pipeline auto-generate the test file:

   ```bash
   python3 scripts/customrv.py from-c scripts/examples/myop_demo.c
   # Generates scripts/tests/myop.c automatically.
   ```

2. **Hand-written** — for `arith_expr` / `closed_form_loop` configs,
   add `tests/<mnem>.c` by hand. Keep it tiny: one function whose
   body is exactly the GIMPLE shape your matcher recognises, with
   the inputs threaded through function parameters so the optimiser
   does not constant-fold them away.

Then run:

```bash
bash scripts/05_test.sh <mnem> $HOME/riscv-install
```

The script invokes `gcc -m<mnem> -O2 -fno-schedule-insns -fno-schedule-insns2 -S`
and greps the output for `^\s*<mnem>\b`. It also prints the
`-fdump-tree-<mnem>rec-details` hint if the mnemonic is missing.
